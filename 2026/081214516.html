前端版本无感切换实战：发布后不打断用户的完整方案

后台管理类单页应用（SPA）在发布新版本时，经常会遇到一类棘手问题：用户在页面里操作到一半，突然页面加载失败，刷新后才恢复正常。这背后往往是前端静态资源版本错位问题。本文记录我在实际项目中沉淀的一套”无感切换”方案。

问题现象

Vite + React 单页应用，页面模块通过动态 import 懒加载。生产环境发布新版本后，偶发出现页面加载失败，刷新后恢复。

典型控制台错误：

用户看到的是统一错误页，例如”页面加载失败”。刷新后通常恢复，因为刷新会重新获取最新的 index.html 与资源引用。

根因

这是前端静态资源版本错位问题，不是普通 React 渲染异常。

发生链路：

  1. 用户浏览器仍运行旧版本入口代码。
  2. 旧版本代码在切换菜单或进入懒加载页面时，请求旧 hash 的 chunk。
  3. 新版本部署后，旧 /assets/*.js 已被删除或 CDN/源站不再提供。
  4. 浏览器请求旧 chunk 返回 404。
  5. React 懒加载失败，ErrorBoundary 展示”页面加载失败”。
  6. 用户刷新后获取新版入口文件，资源引用更新，因此恢复正常。

核心矛盾：

解决目标

目标不是每次发现异常都强制刷新，而是让用户在版本发布时尽量无感：

  • 用户正在使用旧版本时继续可用。
  • 新版本发布后，前端能感知但不打断当前操作。
  • 用户切到后台、失焦或重新进入页面时自然切换到新版本。
  • 真的遇到 chunk 丢失时，自动恢复一次，避免停留在错误页。

部署侧方案（根治关键）

部署侧是根治关键。

保留旧 assets

/assets/* 文件名带 hash，应长期缓存并保留一段时间。发布新版本时不要立即删除旧资源。

建议：

  • 保留最近 7-30 天的 assets。
  • 或保留最近 N 个版本的 assets。
  • 旧资源清理放到独立延迟任务，不放在发布流程中即时执行。

原子化发布顺序

推荐顺序：

  1. 上传新版本所有 /assets/*。
  2. 确认新 assets 上传完成。
  3. 再切换 index.html。
  4. 再切换 /version.json。

禁止：

  • 先覆盖 index.html 再上传 assets。
  • 发布时删除旧 assets。
  • 让 CDN 中的 HTML 和 assets 命中不同版本策略。

缓存策略

原因：

  • index.html 是资源清单入口，需要尽快重新校验。
  • /version.json 用于前端探测新版本，不能被长缓存。
  • /assets/* 文件名带 hash，可以长期缓存。

发现新版本后不立即刷新

当 /version.json 中的 buildTime 与当前运行时代码版本不一致时：

  1. 清理可能导致权限误判的运行时缓存。
  2. 标记当前页面存在待切换版本。
  3. 不立即刷新。
  4. 等页面隐藏或失焦后静默刷新。

这样用户正在操作页面时不会被打断。

页面后台静默刷新

当页面满足以下任一情况时，可以执行静默刷新：

  • 用户切到其他浏览器标签页。
  • 用户切到其他应用窗口。
  • 浏览器窗口最小化。
  • 移动端切到后台。
  • 当前页面失去焦点。

当前策略总结

用户体验：

  • 正在使用时不被强制刷新。
  • 切走再回来时自然进入新版本。
  • 旧页面请求旧 chunk 时，只要部署侧保留旧 assets，就不会报错。
  • 如果旧 chunk 真的丢失，前端最多自动刷新一次恢复。

验证清单

部署侧：

  • 打开旧版本页面不刷新，发布新版本后继续切换懒加载菜单，不应出现 chunk 404。
  • Network 中旧 hash 的 /assets/*.js 仍可访问。
  • 新开窗口或刷新页面后进入新版本。
  • /version.json 返回最新 buildTime，且不被 CDN 长缓存。
  • index.html 不被长缓存。

前端侧：

  • 页面前台可见且聚焦时，会低频请求 /version.json。
  • 切到其他标签页或窗口后，不再持续轮询。
  • 切回标签页时，会立即检测一次版本。
  • 检测到新版本后，当前操作不被立即打断。
  • 页面失焦或隐藏后，会执行静默刷新。
  • 动态 import 失败时，会自动刷新一次，且不会无限刷新。

注意事项

  • 前端兜底不能替代部署侧保留旧资源。
  • 如果部署侧仍即时删除旧 assets，前端只能通过自动刷新降低影响，无法保证完全无感。
  • 多个标签页各自只能检测自己的可见性和焦点状态，不能互相知道对方正在浏览什么。
  • 浏览器不允许网页知道用户切到的其他标签页内容，只允许页面知道自身是否可见。
