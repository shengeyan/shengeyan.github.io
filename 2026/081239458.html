Next.js RSC 序列化异常：antd 复合组件导致的白屏排查

在 Next.js App Router 中，一个 Server Component 页面使用了 Ant Design 的复合导出组件（如 Typography.Text），结果线上页面白屏、报客户端异常。本文复盘这个 RSC 序列化问题，并解释背后的原理。

背景

项目是 Next.js App Router + Ant Design 的单页应用。某线上页面的 HTML 能正常返回 200 OK，服务端也能产出初始 HTML，但浏览器加载客户端 JS 后进入 Application error。

该页面本身没有直接调用业务 API，内容主要由 Ant Design 组件、图标、CSS Module 和静态配置数据组成。

现象

抓取线上页面 HTML 后，在 RSC 数据流中看到页面内容里多处组件类型被序列化为 $undefined，例如 Typography.Text 相关节点：

这表示服务端传给客户端的 RSC payload 中，原本应该是一个 React 组件引用的位置变成了 undefined。客户端恢复这棵树时无法创建合法组件，于是触发客户端异常。

什么是 RSC 序列化

RSC 是 React Server Components 的缩写，即 React 服务端组件。Next.js App Router 默认把没有 'use client' 的页面和组件当作 Server Component 处理。

RSC 序列化指的是：服务端执行 Server Component 后，不直接把完整 React 组件实例发送给浏览器，而是把组件树、props、文本、模块引用、客户端组件边界等信息编码成一种可传输的数据流（RSC payload / Flight 数据）。浏览器收到这份数据后，再结合已经加载的客户端 JS，把页面恢复成可交互的 React 树。

可以理解为三步：

  1. 服务端渲染 Server Component，得到一棵描述页面结构的 React 树。
  2. Next/React 把这棵树中可以传输的部分编码成 RSC payload。普通 HTML 标签、字符串、数字、对象等可以直接表达；客户端组件需要被表达成可在浏览器中加载的模块引用。
  3. 浏览器加载 RSC payload 和对应 JS chunk，将服务端结果与客户端组件合并，完成水合和后续交互。

RSC 序列化要求传输内容必须是 React 能识别并恢复的内容。普通数据需要可序列化；组件类型需要能被 Next 正确识别为服务端可渲染组件或客户端模块引用。如果一个组件类型在 RSC payload 中变成 undefined，客户端就无法恢复这棵组件树。

在当前 Next.js、React、Ant Design 组合下，Server Component 对 antd 复合子组件的引用没有被稳定地编码成客户端可恢复的模块引用。最终 RSC payload 中出现 $undefined，浏览器端恢复失败。

同类风险也存在于其他 Server Component 页面，同样使用 const { Text } = Typography。

修复涉及使用该复合组件的多个页面文件。同时修正 Web 验证脚本，避免 .next/types 缺失或 tsconfig.tsbuildinfo 陈旧时，tsc 继续引用不存在的旧 route type 文件。

验证结果

执行了模块级 lint 和 build，均通过。

构建产物验证：

  • 修复前，RSC 数据中页面内容包含多处 ["$","$undefined", ...]，对应页面内 Typography.Text。
  • 修复后，页面在 RSC payload 中变为 ClientPageRoot，页面主体由客户端页面 chunk 承载，不再把页面内部 Ant Design 复合组件错误序列化为 $undefined。

经验沉淀

  1. Next App Router 中，使用 antd 这类客户端 UI 组件库时，页面边界要保守。含交互、主题、复合组件、运行时上下文依赖的页面，应优先显式加 'use client'。
  2. Ant Design 的复合导出，例如 Typography.Text、Typography.Title、Descriptions.Item、Empty.PRESENTED_IMAGE_SIMPLE，在 Server Component 中需要特别谨慎。
  3. 构建通过不等于 RSC payload 可被浏览器正确恢复。线上出现客户端异常时，应检查生成的 RSC payload 是否存在异常模块引用或 $undefined。
  4. lint 和 build 不应并行读写同一个 .next 目录，否则可能出现 route type 被清理时 tsc 同时读取的竞争问题。
  5. tsc --incremental 可能保留已删除的 .next/types 文件引用。验证命令中关闭增量缓存可以减少误报。
